# Validation and limitations

The six automated tests pass on Linux with Python 3.12. Tests compare independent Schoof and BSGS point counts with a direct quadratic-character count for every admissible quarter-point prime below 1000. They also compare complete Miller outputs with the original rational-sequence recurrence, check Frobenius residues modulo 3, 5, 7 and 11, and verify the odd division-polynomial degrees. Larger cross-checks include all seven paper primes and 1,000,000,009.

The BSGS low-order test ensures every Hasse-interval annihilator is retained. Grid tests reject 1,000,000,007, duplicate inputs, invalid factors and unsupported input sizes. A forced deadline test checks process termination and the absence of fabricated timings in CSV/JSON exports.

A fresh seven-prime benchmark with all four methods and 11 batches completed with 28 successful, agreeing result rows. Every method returned B=33, a=79, U=43 at p=97. The run's machine, source hashes and protocol are in `example_results/paper_seven/benchmark.json`. Its table and four charts are included as a demonstration, distinct from the historical paper appendix.

The retained Harvey full validation additionally checks all small-prime stopping indices, matrix multiplication order, the forced arbitrary-precision path, and invalid inputs. The retained validation passed 10,809 stopping-point queries across 92 primes, 2,130 exact-binomial checks, 328 quarter-point cross-checks, 26 forced arbitrary-precision cross-checks, 7 large-modulus checks, and 3 invalid-input checks. The full report is `example_results/harvey_validation.json`.

Finite checks do not replace review of the mathematics or of the new implementations. An additional three-prime run at 1,000,000,009, 10,000,000,033 and 100,000,000,069 completed with all four methods and three batches, with all 12 result rows agreeing. Its files are in `example_results/larger_three`. The live Linux GUI smoke test also passed: eight correct small-prime result rows, all four chart tabs rendered, CSV/chart exports completed, and cancellation left a valid partial record. A screenshot is included as `GUI_preview.png`. Native Windows execution is not verified here. The point-counting backends are elementary Python implementations and are not intended to stand in for the fastest available Schoof or BSGS implementation. The app only benchmarks the quarter-point family, not arbitrary curves, every stopping point or the complete generic Corollary 4 workflow.
