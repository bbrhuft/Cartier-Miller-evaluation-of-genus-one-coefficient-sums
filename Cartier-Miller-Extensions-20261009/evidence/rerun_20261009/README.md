# Validation rerun, 9 October 2026

Every validator was run from a scratch copy of this release layout, so that the retained evidence files stayed unchanged. The command was `python -B -E -s <script>`, with 17 jobs running in parallel on two cores. RUN_SUMMARY.json records each command, its exit status and its wall time, along with the Python, SymPy, cypari2 and PARI versions. logs/ holds the standard output of each job, plus the progress output that indep_attack.py writes to standard error. All 17 jobs passed. The wall times are indicative only and are not benchmarks.

Most regenerated results matched the retained ones exactly, apart from environment, timing and source-hash fields. Five files differed in content, and they are kept in regenerated/ under their original relative paths. In four of them the difference is new evidence. PARI was available for this run but not for the original consolidation run, so validate_depth_three.py filled the PARI trace column for every family member. All 2,640 PARI `ellap` traces equal the Legendre-symbol traces; the validator asserts this. The members, large-prime and CM-preparation CSVs gained the same column. In the fifth file, indep_attack_results.json, the stored record predates the consolidation hardening of the depth-three recognizer, and the rerun shows the current behaviour. Type-confused inputs now raise an explicit ValueError rather than an incidental TypeError or a status answer. Two tampered certificates are rejected with clearer reasons: one with only its stored reverse endpoint altered, which the old record listed as accepted, and one with missing parameters. Neither result changes a mathematical claim.

The replacement closure validator was run separately. Its record is research/isogeny_closure_20261006/replacement_validation_20261009/validation.json.
